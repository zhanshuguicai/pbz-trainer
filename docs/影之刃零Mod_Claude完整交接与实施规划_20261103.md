### 版本与适配结论

| 操作 | 血量证据 | 血瓶证据 | 战斗证据 |

## 9. P3：架构选择与管理器

建议 Windows 管理器采用 `.NET 8 + WPF`，游戏适配采用 UE4SS Lua，进程间用本机 IPC；这是待工具链确认的候选。
先检查 SDK、目标系统和 UE4SS Lua API/IPC 能力，再写 ADR 定案；没有已建工程、协议或可复用管理器。
若 Lua 无合适 IPC 能力，先评估受支持桥接方式与维护代价，不临时开放公网端口。

建议分层：游戏适配 → 快照/事件 → 各 Mod 服务 → 管理器；模块通过版本化接口协作。
管理器功能：游戏/适配状态、版本兼容检查、三字段诊断、各 Mod 独立启停、热键配置、音乐文件与音量、备份与恢复、日志导出。
热键检测冲突与录入反馈；默认全关闭，失败明确原因，不能显示“已启用”而游戏端未确认。
配置原子写入、版本迁移留备份；适配不匹配时关闭相关能力，并提供可恢复的诊断信息。
管理器崩溃不应卡住游戏；音乐模块异常不影响采集，游戏掉线后命令失效并重建会话。
备份、恢复、安装和卸载按明确清单；恢复前展示目标和日期，验证游戏退出且避免覆盖更新后的进度。

### 本机通信与写入边界

- 优先当前用户 ACL 限制的命名管道等本地通信；若选回环 TCP，限制本机绑定并验证客户端会话，禁止任意网络暴露。
- 协议包含版本、会话、请求 ID、长度上限、参数类型与范围、超时及结果；过期会话或不兼容版本直接拒绝。
- 客户端本地校验不替代游戏端校验；白名单仅开放已实现命令，不接受任意 Lua、地址、函数名或表达式执行。
- 只读命令与玩法写入分开；写入在游戏线程排队，执行前重验对象、版本、场景与前置条件，回读并返回真实结果。
- 命令重试具备幂等/去重策略；关闭 Mod、失联或会话切换取消待执行操作，禁止迟到命令修改新角色。

## 10. P4：三个 Mod 的行为与验收

### Mod 1：自动弹反及红蓝攻击应对

先采集玩家受击目标、敌人攻击阶段、红蓝类型、可防御性和动作窗口，再形成实测映射表。
不能假设“红=某动作、蓝=某动作”；无法识别的攻击保持无自动动作，并可诊断。
建议只在有效战斗、本地角色存活且可控制时工作；菜单、过场、加载、死亡和未知状态立即暂停。
使用游戏已有动作入口或经验证的输入路径；明确冷却、防重入、目标选择和连段阶段，避免逐帧无条件触发。
验收覆盖普通/红/蓝/不可应对攻击、多个敌人、距离变化、连续攻击、手动输入竞争；记录成功/误触/漏触。
热键切换有状态提示，关闭后无残留动作；性能和可接受误触标准在实测后与用户确定。

### Mod 2：事件音乐

建议战斗状态机为 unknown/outOfCombat/inCombat，只有确认新战斗才创建 battleId 并重置一次标记。
每个 battleId 保存 halfHealthTriggered 与 flaskEmptyTriggered；恢复满血或同战斗再次半血不会再播 aizo。
血量/最大值或血瓶无效时暂停判断，不拿缓存补触发；恢复后是否追补由规则确认，默认不追补历史边沿。
用已确认的半血入战规则、脱战确认、死亡行为与双事件优先级；不要在开发时悄悄决定。
音乐使用单一播放控制器，支持停止、切曲、音量和短淡入淡出；找不到文件时清晰报错且不影响其他 Mod。
验收：半血一次/同战多次/新战重触发、正数到零/初始零/补瓶、双事件同刻、死亡/读档/脱战抖动、丢样和重复样本。

### Mod 3：物品数量修改

“所有物品”是用户目标，不能在未枚举前承诺完全覆盖；先生成物品类别与可写能力表。
调查消耗品、材料、货币、装备、任务物品、唯一物品及其他实际存在类别；以实测分类为准，不伪造 ID。
区分已持有数量修改与生成未持有物品；后者是否属于具体产品范围先明确，避免把空项批量生成当修改。
优先游戏已有库存事务入口，保证堆叠上限、容量、持久化和 UI 同步；直接改字段需证实一致性后再选。
唯一/任务/剧情项先标受限并说明原因；逐项证实安全事务才开放，不能把数量改大造成重复唯一实例。
UI 展示 ID、名称、类别、当前量、可接受范围、支持状态；搜索、筛选、预览差异与确认执行。
写入前新备份，先单项最小变化、回读、跨菜单及重载验证；成功后才逐步扩大类别和批量功能。
验收含 0、合法上限、越界拒绝、溢出、负数、背包满、存档重载、唯一/任务项保护及失败部分回滚。
接入阶段的只读约束不等于全项目禁写：未来物品修改在原用户授权目标内，备份后按已验证最小范围写入。

## 11. P5：测试、打包与止损

纯事件状态机用录制快照做确定性测试；协议与配置用版本/异常输入测试；实际对象和游戏行为必须实机验证。
验收记录明确区分静态检查、回放、人工 UI 观察和游戏内动态验证，模拟样本不能替代游戏内通过。
发布先做干净安装、同版本重装、升级、禁用、卸载、未知文件保留和中途失败恢复试验。
包内含版本、兼容 app/build/EXE、依赖来源与 hash、默认关闭配置、操作说明、变更记录、许可证和回滚说明。
包内排除存档、账号路径、私有日志、音乐版权文件及无关工具；音频由用户在管理器中选择。
游戏更新或构建不符就停止玩法命令；适配重新验收后再宣布支持。
出现崩溃、存档差异异常、未知对象写入、签名不唯一或策略拒绝时，停止对应阶段并留证据。
每次试验有有限目标和退出条件；连续失败先复盘差异，再决定修复或升级，不用反复启动代替诊断。

遵循 cost-aware-dispatch：中枢管理与验收，worker 不递归派工；模型是否实际可调用以工具回显为准。
