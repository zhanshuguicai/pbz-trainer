# ADR 0002：从"Mod 管理器"改为集成修改器

- 日期：2026-11-03
- 状态：已采纳（用户提出方向；Claude 定架构）
- 承接：[ADR 0001](0001-architecture.md)（两进程、本地文件通信、判定在 C#、写入在 Lua）全部沿用

## 背景

T4d 完成后，用户要求把管理器做成"高度集成的修改器"，原话："能够锁定血量杀气，锁定能量点数，设计自己的'条件播放器'（diy条件加自己想放的歌，比如阵亡时，开战时，还有现在这两个条件等等），再加上强化物品数量修改器和自动弹反闪避等功能"。

用户随后确认：能量点数 = 绝技能量条 + 影/魂点数；锁定方式 = 锁满；顺序 = 播放器 → 锁定 → 物品 → 弹反。

## 决定

### 产品形态
- 一个程序：影之刃零 修改器（原 PBZManager 工程继续用，界面改为分页）。页面：状态、锁定、条件播放器、物品、战斗辅助、设置/安装。
- 游戏内仍是一个 PBZSuite，功能按模块开关。

### 条件播放器（取代固定的两条音乐规则）
- 规则 = 条件 + 歌曲 + 优先级 + 触发范围（每场一次 / 每次）+ 脱战是否淡出 + 启用。
- 条件第一版：开战、脱战、血量跌破 X%（X 可设）、药喝空、阵亡、重生/读图。后续可加（例如 Boss 战，需要另做探针）。
- EventEngine 只产出"原子事件"（开战、脱战、跌破阈值、喝空、阵亡、重生），不再内置"半血每场一次"；"每场一次"和"同时触发时谁优先"移到规则层。
- 冲突：优先级高的打断低的；低的在高的播放时忽略；同优先级新的替换旧的。
- 原来两条规则迁移为默认规则：跌破 50% → aizo（优先级 1，每场一次，脱战淡出）；药喝空 → 雨爱 DJ（优先级 2，每场一次，脱战淡出）。产品规则 2–4、8 不变。

### 锁定（血量、杀气、绝技能量、影/魂点数）
- 在 Lua 里执行（写入类模块，要求 config.compatible=true），开关由管理器下发，另配热键。
- 先做只读+写入探针：确认写入后游戏界面会刷新、不会被游戏立刻改回、读档后不残留。候选写法：游戏作弊管理器里的现成命令（如 GM_SetHealth，回血 mod 用过）优先，直接写 GAS 属性的 BaseValue/CurrentValue 作为后备。
- 锁满 = 低于上限时补到上限，不改上限本身。

### 物品、战斗辅助
- 物品：按原计划 T5a（只改强化/养成材料与钱的已持有数量）。
- 战斗辅助：原 Mod 1 扩展为自动弹反 + 自动闪避，仍是最后一项，需要单独的调查阶段。

## 后果
- 条件播放器只改管理器侧 C#，不碰游戏，可最先交付。
- 锁定是第一个写游戏内存的功能，需要先过探针验证，再开放给界面。
- 单机游戏、只改本地进程，不涉及联网或他人；EXE 里有 Denuvo 相关字符串，本项目不绕过也不修改它，只通过 UE4SS 反射读写游戏对象。
